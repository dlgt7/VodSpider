================================================================================
                          XBPQ 插件调用示例
================================================================================

XBPQ 是 CatVodSpider（VodSpider）框架的影视爬虫，以 && 正则截取为核心规则语法，
支持中英文双键配置、CSS/Jsoup 选择器模式、多线聚合、Cloudflare/宝塔反爬绕过、
图片代理、弹幕加载、M3U8 解析、{{变量}} 模板、动态域名切换、镜像域名等特性。

================================================================================
一、TVBox 外挂调用基本格式
================================================================================

在 TVBox 配置 JSON 的 sites 数组中添加：

{
    "key": "csp_XBPQ_站点名",
    "name": "站点显示名(XBPQ)",
    "type": 3,
    "api": "csp_XBPQ",
    "searchable": 1,
    "quickSearch": 1,
    "filterable": 1,
    "ext": "站点配置JSON的路径或URL",
    "jar": "XBPQ.jar 的路径或URL"
}

参数说明：
- key：唯一标识，建议 csp_XBPQ_ 开头
- name：显示名称
- type：固定 3（Spider 类型）
- api：固定 "csp_XBPQ"（对应 com.github.catvod.spider.XBPQ 类）
- searchable：1=支持搜索，0=不支持
- quickSearch：1=支持快搜，0=不支持（当前 quick 参数被引擎忽略，快搜与普搜一致）
- filterable：1=支持筛选，0=不支持
- ext：站点规则 JSON，支持：
    * clan://TVBox/xxx/xxx.json     （clan 本地路径）
    * http://xxx.com/xxx.json       （网络 URL，懒加载）
    * 直接 JSON 字符串              （内联配置）
- jar：XBPQ.jar 的位置

场景 6：JSON 搜索模式（AJAX suggest）
────────────────────────────────────────────────────────────────

写法 A（扁平键 + 搜索模式=0，JSON 自动探测）：
{
    "站名": "JSON搜索示例",
    "主页url": "https://www.example.com",
    "搜索url": "https://www.example.com/index.php/ajax/suggest?mid=1&wd={wd}",
    "搜索模式": "0"
}

说明：搜索模式=0（默认）优先 JSON 解析：parseJsonSearchResult 递归探测
同时含 id/name 字段的数组并映射标准字段（vod_id/vod_name/vod_pic/vod_remarks）。

写法 B（搜索JSON 字段组显式指定字段名）：
{
    "站名": "JSON搜索示例2",
    "主页url": "https://www.example.com",
    "搜索url": "https://www.example.com/api/search?wd={wd}",
    "搜索JSON路径": "data.list",
    "搜索JSONID": "id",
    "搜索JSON名称": "name",
    "搜索JSON图片": "pic",
    "搜索JSON状态": "note"
}

写法 C（分节 search 子对象，vod_id 等值 = JSON 字段名）：
{
    "站名": "JSON搜索示例3",
    "主页url": "https://www.example.com",
    "search": {
        "url": "/api/search?wd={wd}",
        "vod_id": "id",
        "vod_name": "name",
        "vod_pic": "pic"
    }
}

注意：扁平 搜索url 的 {wd} 自动 URL 编码；分节 search.url 的 {wd} 原样替换。
     搜索 URL 末尾 ";post" 写法当前无效（postSearch 未接入调用链）。

场景 14：后处理器 [替换:] 用法
────────────────────────────────────────────────────────────────

{
    "站名": "后处理示例",
    "主页url": "https://www.example.com",
    "分类": "电影$1",
    "分类url": "https://www.example.com/{cateId}/page/{catePg}.html",
    "数组": ".item&&</div>",
    "图片": "data-src=\"&&\"[替换:img.example.com>>cdn.example.com]",
    "标题": "title=\"&&\"[不包含:预告]"
}

说明：值末尾追加后处理器，提取后执行：
  [替换:旧>>新#旧>>新]  文本替换，# 分隔多组，旧串含 * 时转 .* 通配正则
  [包含:关键词]          包含才保留，否则返回空
  [不包含:关键词]        不含才保留，否则返回空
注意：[工具:xxx] 工具链（解b64/SHA/AES 等）本版未实现，请勿使用。

场景 16：;; 截断与 page_end_marker 翻页终点
────────────────────────────────────────────────────────────────

{
    "站名": "截断用法示例",
    "主页url": "https://www.example.com",
    "分类": "电影$1",
    "分类url": "https://www.example.com/vodtype/1-html;;https://www.example.com/vodshow/1-page/{catePg}.html",
    "数组": ".vodlist&&</ul>",
    "标题": "title=\"&&\"",
    "链接": "href=\"&&\"",
    "翻页终点标记": "没有更多"
}

说明：
- 分类url 含 ";;" 时截取 ;; 之前的部分作为请求 URL，;; 之后的部分被丢弃。

  框架据此停止翻页。常用于后端无分页或已到最后一页的场景。

场景 17：list_total 精确控制总页数
────────────────────────────────────────────────────────────────

写法 A（硬编码总条数，适合 API 站点）：
{
    "站名": "总数控制示例",
    "主页url": "https://www.example.com",
    "分类": "电影$1",
    "分类url": "https://www.example.com/api/vod?type=1&page={catePg}",
    "列表模式": "1",
    "列表JSON路径": "data.list",
    "列表JSONID": "vod_id",
    "列表JSON名称": "vod_name",
    "列表总页数": "500"
}

写法 B（HTML 站点，依赖猜测失败时的精确值）：
{
    "站名": "总数控制示例2",
    "主页url": "https://www.example.com",
    "分类": "电影$1",
    "分类url": "https://www.example.com/list/1/page/{catePg}.html",
    "数组": ".item&&</li>",
    "标题": "title=\"&&\"",
    "链接": "href=\"&&\"",
    "总页数规则": "共{total}条"
}

说明：
- list_total 值为纯数字时，pagecount = ceil(list_total / 当前页条数)。
- list_total 也可写为 && 截取规则（如 "共{total}条"），引擎会先尝试截取 HTML。
- 不配置时引擎自动猜测（JSON total 字段/mac_total JS 变量/「共N条」文本/分页链接数），
  均失败时兜底 50 页。

场景 18：搜索词分隔符 search_word_sep（空格转 +）
────────────────────────────────────────────────────────────────

{
    "站名": "分隔符示例",
    "主页url": "https://www.example.com",
    "搜索url": "https://www.example.com/search.php?wd={wd}",
    "搜索词分隔符": "+",
    "搜索数组": ".result&&</li>",
    "搜索标题": "title=\"&&\"",
    "搜索链接": "href=\"&&\""
}

说明：
- 扁平搜索 url 中 {wd} 默认经 URLEncoder.encode（空格变 %20）。
- 设置 search_word_sep="+" 后，空格先被替换为 "+"，再经 URLEncoder.encode
  → 最终空格编码为 "+"（Google/Bing 风格搜索）。
- 分节 search.url 写法中的 {wd} 原样替换，search_word_sep 不生效。

场景 20：M3U8 代理解析（proxy:// 直接返回 m3u8 内容）
────────────────────────────────────────────────────────────────

{
    "站名": "M3U8代理示例",
    "主页url": "https://www.example.com",
    "分类": "电影$1",
    "分类url": "https://www.example.com/{cateId}/page/{catePg}.html",
    "数组": ".item&&</li>",
    "标题": "title=\"&&\"",
    "链接": "href=\"&&\"",
    "播放链接": "proxy://do=XBPQ&m3u8=https://cdn.example.com/play/123.m3u8"
}

说明：
- proxy://do=XBPQ&m3u8=URL 让代理服务器回源拉取 m3u8 并补全相对路径。
- 支持 base64 编码的 m3u8 内容（长度>200 且无 :// 时自动探测）。
- 支持 base 参数指定 baseUrl：proxy://do=XBPQ&m3u8=...&base=https://cdn.example.com/
- 返回 Content-Type: application/vnd.apple.mpegurl，播放器可直接播放。

场景 21：图片代理签名校验与安全机制
────────────────────────────────────────────────────────────────

{
    "站名": "图片代理安全示例",
    "主页url": "https://www.example.com",
    "图片代理": "1",
    "代理密钥": "MySecretKey2024",
    "图片代理白名单": "img.example.com#cdn.example.com",
    "图片属性": "data-original",
    "分类": "电影$1",
    "分类url": "https://www.example.com/{cateId}/page/{catePg}.html",
    "数组": ".item&&</div>",
    "标题": "title=\"&&\"",
    "链接": "href=\"&&\""
}

说明：
- 图片代理=1 时，封面图自动包装为 proxy://do=XBPQ&pic=URL&key=MD5(pic+secretKey)&site=Referer
- 签名算法：MD5(原始图片URL + secretKey)，防止第三方滥用代理服务。
- 图片代理白名单（# 分隔）限制仅允许这些域名的图片走代理，超出域名的请求被拒绝。
- 所有回源请求强制经过 SSRF 防护（拦截 127./10./192.168./169.254 等内网地址）。
- 即使 allow_internal=1，proxy 入口也不放行内网地址。

场景 24：动态域名切换（规则加载时生效）
────────────────────────────────────────────────────────────────

{
    "主页url": "https://old.example.com",
    "主页url-c": "https://new.example.com",
    "域名-c": "{{主页url-c}}[替换:.com>>.xyz]",
    "分类": "电影$1",
    "分类url": "{{主页url}}/vod/show/{cateId}/page/{catePg}.html",
    "搜索url": "{{主页url}}/search.php?wd={wd}",
    "数组": ".item&&</li>",
    "标题": "title=\"&&\"",
    "链接": "href=\"&&\""
}

说明：
- 规则加载时 applyDynamicDomain() 执行：
  1. 域名-c 展开 {{变量}} + [替换:] 后处理器
  2. isValidOrigin 校验是否为合法 origin（仅域名+协议，无路径）
  3. 合法则将整份规则中旧 homeUrl 的 origin 全局替换为新 origin
  4. 填充 {{域名-c}} 和 {{主页url-c}} 变量
- 主页url-c 仅作为 {{主页url-c}} 变量来源，不会触发域名切换。
- 域名-c 无效时（如解析失败、origin 不合法），保持原 homeUrl 不变。

五、注意事项
================================================================================

1. jar 包：所有 XBPQ 站点共用同一个 XBPQ.jar，升级 jar 后所有站点同步生效。
2. 配置值约定：留空 / "空" / "&&" 均视为未配置；布尔型统一用 "0"/"1"。
3. 中英文键混用：XBPQKey.norm 统一归一化（大小写不敏感），未登记键原样透传。
4. 解码：搜索关键词 {wd} 自动 URL 编码（扁平搜索url 写法）；详情链接含
   %uXXXX JS 转义自动解码（hexEscapeDecode）。
5. vod_id 为 Base64 编码 JSON（encodeVodId），detailContent 自动解码，
   规则书写者无需关心。
6. SSRF 防护：拦截内网/127/10/192.168/169.254 等地址；内网放行=1 可放行
   普通请求（proxy 入口不受影响）；P2P 链接（magnet/ed2k/thunder 等）
   直接交给播放器。
7. 单条片单解析失败不影响整体列表（skip_bad_item=1 默认跳过）。
8. 图片净化：默认封面兜底 + 懒加载属性（图片属性）提取真实地址，
   img_attr 优先级最高，否则按 LAZY_IMG_ATTRS 顺序兜底。
9. quick 快搜参数当前被引擎忽略（快搜与普搜行为一致）。
10. 视频过滤词优先级高于嗅探词，命中强制判定为非视频 URL。
11. 选集链接加前缀/加后缀 在播放线路提取时自动应用到每条集数链接。
12. WebView 渲染（web_view 系列键）仅注册未实现，运行时输出告警并忽略；
    特殊分类链接 / 直播url 同样仅注册不消费。
13. [工具:xxx] 工具链、[firstPage=...] URL 语法、";post" POST 搜索
    本版均未实现，请勿在规则中使用。
14. ;; 截断：分类url 含 ;; 时截取 ;; 之前的部分作为实际请求 URL，;;
    之后的内容被丢弃，不适用于双 URL 并存场景。
15. page_end_marker：响应 body 命中标记文本时返回空列表（pagecount=0），
    框架据此停止翻页，适用于后端无分页或已到末页的站点。
16. list_total：纯数字时精确控制总页数；也可写为 && 截取规则，引擎
    先尝试截取 HTML，失败时回退到自动猜测（JSON total/mac_total/共N条/分页链接）。
17. search_word_sep 仅对扁平 search_url 生效（分节 search.url 的 {wd}
    原样替换不受影响）。
18. offset_paging=1 时 {offset}=(页码-1)*pageSize，{limit}=pageSize；
    若 url 不含 {offset} 则 {catePg} 也转为偏移量。
19. proxy:// 所有回源请求（pic/danmu/m3u8）强制经过 SSRF 防护，
    不受 allow_internal 影响；图片代理和弹幕需 secretKey MD5 签名校验。
20. 多线模式：multi_line_array + multi_line_url 必须同时非空才触发，
    最多提取 10 条线路；multi_line_array 为空时走 tryFromLinkMode 备选路径。
21. 动态域名：域名-c 在规则加载时执行 origin 全局替换，主页url-c 仅作
    变量来源；origin 校验失败时保持原 homeUrl 不变。
22. 常量边界：首页每分类最多聚合 20 条（DEFAULT_HOME_MAX_VIDEOS）；
    单页列表最多 100 条（MAX_PAGE_ITEMS）；无法推测总页数时兜底 50 页；
    首页 HTML 缓存 5 分钟（HOME_CACHE_TTL_MS）。
